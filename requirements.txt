# Runtime dependencies for the backend, pinned from the known-good venv:
#
#     backend/venv/Scripts/python.exe -m pip freeze
#
# WHY THIS FILE EXISTS
# --------------------
# There was no runtime requirements file in this repository - the note in
# ``backend/requirements-dev.txt`` said so and called it a deployment risk. It is one: a host
# that builds from this repository (Railway, Render, Fly) has nothing to install, so the
# application either never starts or starts with whatever the builder happened to guess, and the
# symptom is a 502 from the edge with no error anywhere in the app.
#
# WHAT IS NOT HERE
# ----------------
# The test-only packages that ``backend/requirements-dev.txt`` pins on top of this list:
# pytest, pluggy, iniconfig, httpx2, httpcore2, pyee and playwright. None of them is imported by
# the application, ``serve.py`` or any runtime module - ``playwright``/``httpx`` appear only in
# ``backend/tools/profile_endpoints.py``, an operator script - and a browser-automation stack
# installed on a host we pay for is build time and disk with no runtime use.
#
# Everything else is the freeze verbatim, including the transitive pins: a manifest that leaves
# resolution to the host is a manifest that installs a different application than the one that
# was tested.
#
# ``backend/tests/test_deployment_manifest.py`` fails if a runtime import loses its pin, or if a
# test-only package comes back in.
